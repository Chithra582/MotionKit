# RULES.md - MotionKit Operational Constraints & Guardrails

> **Specification:** OpenGAP Spec 0.1.0  
> **Agent Name:** MotionKit Agent (`motionkit-agent`)  
> **Enforcement Level:** Mandatory & Deterministic  

---

## 1. Academic Integrity & Anti-Plagiarism Guardrails

1. **Zero Tolerance for Plagiarism**: Duplicating community Figma files without substantial original implementation or copying fellow contributors' submissions results in immediate evaluation failure and disqualification.
2. **Attribution Requirement**: Utilizing public icon sets (e.g., Feather, Lucide, Material) or stock photography (Unsplash) requires explicit attribution in the task submission description.
3. **Original Construction Verification**: Components must be constructed natively within Figma using proper frames, shapes, and vectors rather than embedded raster screenshots.

---

## 2. Directory Containment & Submission Boundaries

1. **Task Folder Isolation**: Contributions must be placed strictly within the designated task folder (e.g., `1-loader/`, `2-tab-navigation/`, `3-dropdown/`) in a dedicated subfolder matching the contributor's GitHub handle or issue number.
2. **Deliverable Standards**: Submissions must provide:
   - Public view/inspect Figma file link.
   - Screen recording preview (GIF or MP4) demonstrating interactive prototyping states.
   - Design rationale notes explaining Auto-Layout decisions.
3. **Time-Window Enforceability**: Tasks submitted after the stated deadline cannot be scored for competitive points without explicit mentor grant.

---

## 3. Data Governance & Student Privacy Standards

1. **FERPA & GDPR Compliance**: Student contributor contact details, roll numbers, and Discord handles must remain protected with zero commercial data collection.
2. **Token & Link Security**: Personal Figma access tokens or private API keys must never be committed to repository branches or logged in review summaries.
3. **Right to Erasure**: Contributor assets and historical review notes may be removed upon request in accordance with open-source project privacy rules.

---

## 4. Human-in-the-Loop & Mentor Primacy

1. **Mentor Evaluation Finality**: Automated linting validates technical criteria (Auto-Layout, variant counts, contrast), but subjective points (Visual Attractiveness, Design Thinking) rest with human mentors (Soham Donode & Organizers).
2. **Review Appeal Window**: Contributors can request clarification on evaluated Minimum Design Criteria (MDC) through the official GeekHaven OpenCode Discord channel.
